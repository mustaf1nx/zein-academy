# Zein Academy — исправления 1.1.0

Обновление исходного проекта из `zein-academy-main (4).zip` от 24.09.2026.
Сервер FastAPI, база SQLAlchemy, основной интерфейс `index.html`.

## Что изменено

Совмещён доступ администратора и преподавателя для четырёх дополнительных
админских учётных записей. Расписание отображает получасовые деления, сохраняет
минуты начала и окончания и различает кабинеты разных филиалов. Отчёты по умолчанию
открываются за период с первого числа текущего месяца по сегодняшний день.

Проведённый урок теперь имеет отдельную запись `LessonReport`: группа, дата,
конкретный слот, фактический преподаватель, ставка и версия отчёта. Назначение
другого учителя группе не меняет уже проведённые уроки. Исправление отчёта
администратором не переносит зарплату на администратора. Сохранение проверяется
сервером, повторная отправка и устаревшая версия не создают второй оплачиваемый урок.

Это обновлённые исходники, а не уже выполненное обновление работающего сервера.
Реальная база пользователей в архив не включена и здесь не изменялась.

## Перед обновлением существующего сайта

**Сначала прочитайте `DEPLOYMENT_RU.md`. Не заменяйте существующую базу пустой
`zein.db`, не запускайте старые и новые обработчики записи одновременно.**

Миграция добавляет таблицы и поля без удаления старых строк журнала. Там, где
исходные данные неоднозначны, отчёт помечается для сверки, а не назначается
текущему преподавателю. Старую утраченную информацию невозможно определить
достоверно только по этому архиву.

## Локальный запуск новой тестовой установки

Создайте виртуальное окружение Python, активируйте его и установите зависимости:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`. Сгенерируйте секрет и внесите его в `SECRET_KEY`:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
python migrations.py
uvicorn main:app --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. Секрет нельзя оставлять пустым, публиковать в Git
или менять при каждом запуске. В рабочей установке сохраните существующий
надёжный секрет; слабый стандартный секрет из старой версии необходимо заменить.

При первом запуске отсутствующие учётные записи создаются автоматически.
Пароли задаются приватными переменными окружения либо генерируются в закрытый
файл `.secrets/initial_accounts_*.json`. В журнал сервера выводится только путь.
Существующие пароли не сбрасываются. Порядок подготовки аккаунтов описан
в `DEPLOYMENT_RU.md`.

## Документация и проверки

- `AUDIT_RU.md` — причины ошибок, исправления и оставшиеся риски.
- `DEPLOYMENT_RU.md` — резервная копия, миграция, аккаунты и проверка сервера.
- `TEST_RESULTS_RU.md` — 54 серверные проверки, 21 браузерная проверка и ограничения.
- `validation/` — фактические результаты и снимки интерфейса на тестовых данных.

Основные команды тестирования:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m playwright install chromium
python tests/browser_smoke.py
```

Тесты используют изолированные временные SQLite-базы, не рабочую базу. Браузерный
сценарий соединяет Chromium с FastAPI TestClient без внешней сети; это не проверка
боевого домена, TLS или PostgreSQL. Для системного Chromium можно задать
`BROWSER_EXECUTABLE`.

## Важные границы

Сохранена прежняя схема оплаты **за проведённый урок**. Имя поля `hourly_rate`
историческое: получасовые деления расписания сами по себе не меняют зарплату.
Перевод на оплату за фактические минуты требует отдельного согласованного правила.

`APP_TIMEZONE` должен оставаться `Asia/Almaty`, поскольку эту зону использует и
интерфейс. Старые публичные ссылки на заморозку только с номером ученика больше
не принимаются: создайте новые подписанные ссылки через интерфейс.

Сервер обслуживает `/` из `index.html`. Файлы `main.html` и `autorization.html`
сохранены из исходного архива как старые макеты; рабочий маршрут их не использует.
